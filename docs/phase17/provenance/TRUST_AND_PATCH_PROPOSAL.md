## Where actual events must originate

- `Program.cs:469-478`: after configured source bytes and MAP are read by the
  producer, `RootDeclared(startAddr)` and ordered canonical
  `MapSeedDeclared(seed)` events. Record exact raw/normalized MAP digests,
  root source config and selected project profile identity. Do not infer them
  from a parsed manifest supplied by the caller.
- `Program.cs:550-574`: the MAP queue consumes only previously unvisited
  seeds; record `AlreadyVisited`, `SeedAttemptQueued`, or `SeedSoftSkip`.
  A MAP entry reached previously from required WALK inherits WALK origin,
  rather than becoming speculative just because MAP mentions it.
- `Program.cs:599-665`: `IndexedParallel.For` can complete out of order;
  capture per-index attempt observations in worker-owned slots, then commit
  observer events in deterministic `batch[i]` order on the serial loop.
  Do NOT append a global event list under workers' completion order.
- `Program.cs:667-687`: speculative exceptions are currently saved only
  to a thread-safe `speculativeSkips` list; preserve a typed per-attempt
  failure outcome and mark all failed speculative **descendants**, not just
  original MAP entries. Never put exception contents or Nintendo bytes in
  public logs.
- `Program.cs:720-760`: immediately after state actually commits, append
  `TranslationCommitted`, then `TargetDiscovered(parent,target)` on an
  actually added visited target; record dedup separately. Do not use
  downstream `Build.DirectCallDependencies` as a substitute for this origin.
- `Program.cs:799-834`: note boundary repair and which earlier committed
  SSA snapshot has been superseded. A later repair may change target sets;
  a provenance graph that ignores supersession can falsely certify stale
  caller-target edges.
- `Program.cs:875,1336-1493`: use actual `emissionAddresses` and the final
  `BaseTranslationFunctionMetadata` path/SHA for `OutputEmitted` only after
  output/bundle bytes are durable and have been re-hashed. A failed output
  must not leave an apparently completed signed run.

## Required schema v2, not compatible with toy v1 event order

A genuine producer **must not** call `OutputEmitted` during `CommitResult`
just to satisfy Phase16's synthetic v1 verifier. Actual output is emitted
in a later pass. Propose a new independent `eventsVersion=2` including:

`root_declared`, `map_seed_declared`, `candidate_attempted`,
`translation_committed`, `target_discovered`, `candidate_skipped`,
`candidate_deduplicated`, `boundary_superseded`, `output_emitted`,
`run_completed`.

Each has a monotonic serial publication seq and stable run ID. If worker
results are included, bind them to canonical batch index and final SSA
fingerprint. Events refer to actual source regions (owner-private); public
reports should use abstract counts and codes. A sidecar should carry
independent raw input/MAP/config hashes, exact producer binary/source pin,
compiler flags, translator project/profile, normalized source sections,
metadata file digest, source-bundle digest, and path/content hashes of all
emitted files. The translation identity hash currently NULL is not a
substitute for original DOL provenance.

## Independent authenticity trust model

The **only** useful trust assertion would be made by a verifier separated
from the untrusted producer and sidecar writer, holding independent
precommitted source identity, run nonce, producer binary fingerprint,
configuration, original input hashes and a trusted observation/signature
root. The producer must not be able to write that trust root. Suggested
owner-private design:

1. Privately verify signed-off source files, exact executable/hash and
   translator build in a sandbox. Hold an observer challenge nonce that the
   sidecar writer cannot select; establish run context before input decode.
2. Observer watches the trusted instrumented process and captures both
   canonical event stream and artifact commit result. A simple SHA/HMAC key
   stored beside the sidecar, or an anchor file generated by the same toy
   process, is **self-certification**, not attestation.
3. After ALL outputs are closed and verified, independently sign a digest
   chain covering the challenge, run ID, source/config/MAP, final event
   bytes, metadata, original output artifact hashes and status. A partially
   failed translation must not produce a release-success attestation.
4. A different verifier checks signature/trusted observer authorization,
   source identity and causal consistency, then **separately** validates
   W03/ABI/HLE dependencies and owner permission. Source provenance alone
   is not proof that a Wii function executes correctly.

**Current status:** none of the above trusted observer/signing process
exists; synthetic Python event replay always returns
`producer_attested=False`, `authentic_release_eligible=False`. The
existing W01 auditor's MAP==metadata equality remains fail-closed and
**must not** be relaxed by this proposal alone.
