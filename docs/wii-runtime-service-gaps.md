## Implemented this branch: smallest safe synthetic virtual-tick service

- C++ tick_snapshot.cpp exports nsmbw_services_tick_store32(guestAddress,low32) and nsmbw_services_tick_status; one aligned 32-bit checked W04 guest RAM store, strict MEM1/MEM2 only, MMIO never dispatched.
- JS tick_host.mjs accepts a **BigInt u64 host virtual count**, rejects negative/non-BigInt/regressing/overflow, limits host advance to 60,750,000 ticks per call and only advances its state after successful W04 write. A per-real-Wasm-instance native lifetime claim flag enforces ONE clock authority across cached/uncached aliases, structural forwarding facades, and duplicated ESM URL evaluations. A nonconfigurable JS Symbol.for property remains a secondary early per-facade check, NOT the canonical authority. See web-runtime/runtime-services/PHASE7_CLOCK_OWNERSHIP.md for reserved host-control registration ABI, limitations and trust boundary. The owner stays for that module lifetime; nonextensible modules fail closed on registration. `reset(0n)` cannot rewind a live guest clock: the owner verifies that the module-wide W03/W04 reset cleared all resident pages, runnable/paused/done/faulted/cancelled contexts and trace before decreasing virtual time. Reset never secretly clears guest RAM. The full reset is explicit and checked first; no external clock epochs are guessed. Low32 wraps modulo 2^32 without pretending to implement an authentic 64-bit PPC timebase.
- build_tick.ps1 compiles one real WASM: W03 CPU + W04 RAM + W07 checked device policy + unchanged W08 input + new tick service. Normal binary installs no TEST-only callbacks. The existing fixed synthetic CPU reads low32 from 0x80008000 like any checked word and computes a synthetic result, **not OSGetTime semantics**.
- Tests exercise real Emscripten Wasm in Node and Chromium, low32 wrap, 3 CPU contexts, 128 resets, quota 0 and RAM rollback, invalid/negative/overflow/oversized samples, MMIO rejection, reentrancy and separate module isolation. All original game bytes remain outside GitHub.
